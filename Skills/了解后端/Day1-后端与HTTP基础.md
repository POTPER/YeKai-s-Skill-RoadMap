## 2. 什么是后端（回顾与补充）

- **前端**：运行在浏览器/客户端上，负责界面展示和与用户交互。
- **后端**：运行在服务器上，负责业务逻辑、数据存储、安全校验，对用户不可见。
- 典型流程：
  1. 前端发起 HTTP 请求（例如：点击“登录”按钮）。
  2. 后端收到请求，做：验证 → 处理业务 → 访问数据库 → 生成结果。
  3. 后端把结果通过 HTTP 响应返回给前端。
  4. 前端根据结果更新界面。

你可以把后端想象成“餐厅后厨”：
- 服务员 = 前端，面对顾客。
- 厨房 = 后端，真正做菜、配菜、出餐。
- 菜单/点单系统 = 接口设计和数据结构。

## 3. HTTP 基本概念

HTTP（HyperText Transfer Protocol）是浏览器和服务器之间最常用的通信协议。

### 3.1 URL 结构

一个常见的 URL 例子：

```text
https://example.com:443/api/users?id=123
```

它可以拆开理解：
- `https`：协议（HTTP 或 HTTPS）。
- `example.com`：域名（服务器地址）。
- `:443`：端口（常见：80、443，可以省略）。
- `/api/users`：路径（访问服务器上的哪一个资源/接口）。
- `?id=123`：查询参数（传递简单数据）。

### 3.2 HTTP 请求的组成

一个 HTTP 请求大致分为三部分：

1. **请求行**：方法 + 路径 + 协议版本
   - 示例：`GET /api/users?id=123 HTTP/1.1`
2. **请求头（Headers）**：描述本次请求的附加信息
   - 常见：`Content-Type`、`User-Agent`、`Authorization` 等。
3. **请求体（Body）**：要发送给服务器的数据（一般在 POST/PUT 中出现）。

常见请求方法：
- `GET`：获取数据（读）。
- `POST`：提交数据（新增）。
- `PUT`：整体更新某个资源。
- `PATCH`：部分更新某个资源。
- `DELETE`：删除资源。

### 3.3 HTTP 响应的组成

服务器返回的响应主要包含：

1. **状态行**：协议版本 + 状态码 + 状态文本
   - 示例：`HTTP/1.1 200 OK`
2. **响应头**：响应的一些元信息
   - 例如：`Content-Type: application/json`。
3. **响应体**：真正的数据内容（HTML、JSON、图片等）。

常见状态码大类：
- 2xx：成功（例如 200 OK，201 Created）。
- 3xx：重定向（例如 301 Moved Permanently）。
- 4xx：客户端错误（例如 400 Bad Request，401 Unauthorized，404 Not Found）。
- 5xx：服务器错误（例如 500 Internal Server Error）。

## 4. 实际观察一次 HTTP 请求

### 4.1 使用浏览器开发者工具

1. 打开任意一个网页（例如百度、知乎等）。
2. 按下 `F12` 或右键选择“检查/检查元素”。
3. 切换到 **Network / 网络** 面板。
4. 刷新页面，可以看到很多请求列表。
5. 随便点一个请求，查看：
   - **Headers/标头**：请求方法、URL、状态码等。
   - **Preview/预览 或 Response/响应**：服务器返回的内容。

### 4.2 你需要做的事情（实践）

- 找到一个 `GET` 请求和一个 `POST` 请求（如果有的话）。
- 尝试回答：
  1. GET 请求的 URL 是什么？状态码是多少？
  2. 如果有 POST 请求，请查看它的 **Request Payload / Form Data**，它向服务器发送了哪些字段？

你可以把你看到的内容（例如某个请求的 URL、状态码等）复制到聊天里，让 AI 帮你一起分析。
