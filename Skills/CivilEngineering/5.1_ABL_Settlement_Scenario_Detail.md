# 5.1 ABL 实训任务书：训练“沉降鉴定专家”智能体

> **实训背景**: 你是某大型鉴定机构的技术负责人。近期有多栋老旧砖混建筑出现裂缝，现场人力严重不足。
> **核心任务**: 在 **Agent Studio** 中构建并训练一个“沉降鉴定专家”智能体，使其能够代替你完成现场勘查、数据判别并输出鉴定结论。

---

## 🎯 任务设计：全周期实训架构

为了完成该任务，你需要像“教练”一样，通过以下四个维度同步打磨你的智能体。记住：**这不是一个线性流程，你可以随时返回任何环节进行迭代。**

### 1. 任务目标 (Objective)
*   **输入**: 建筑虚拟现场、历史地质资料、实时监测数据。
*   **输出**: 符合 JGJ 125-2016 规范的鉴定等级 (A/B/C/D) 及处置建议。

### 2. 实训沙盒 (The Sandbox)
你可以操作的资源包括：
*   **Memory 库**: 包含裂缝高清照片、基坑深度数据、土层勘察报告。
*   **Brain 控制台**: 允许你编写 `IF-THEN` 逻辑，并将 JGJ 125 的条文参数（如 10mm, 1%）注入。
*   **Tool 车间**: 提供电子水准仪、全站仪、裂缝测宽仪，需经过你校准后才能给 Agent 使用。
*   **SOP 画板**: 用于编排 Agent 的思考和行动链。

### 3. 操作模式：迭代工作坊 (Studio Mode)
本实训不强制步骤。建议的“心法”如下：
1.  **感知先行**: 先去现场走一圈，看清裂缝形态。
2.  **规则对齐**: 回到大脑控制台，把看清的“机理”写成逻辑规则。
3.  **工具挂载**: 选好干活的工具并校准。
4.  **试运行**: 在 **Phase 5 (Run)** 运行模拟，如果 Agent 报错或评分低，立即回到相应环节修改。

## Phase 2: 大脑规则注入 (Brain Training)
**目标**：赋予 Agent 基于国家规范的逻辑推理能力，并具备“排除干扰”的鉴别力。

### 2.1 规范原文参考 (Regulatory Text Reference)
智能体的大脑逻辑必须严谨对齐以下规范条文：

#### **A. JGJ 125-2016《危险房屋鉴定标准》**
*   **第 4.2.1 条 (地基危险性判定)**:
    > “当单层或多层房屋地基出现下列现象之一时，应评定为危险状态：
    > 1. 当房屋处于自然状态时，地基沉降速率连续两个月大于 **4mm/月**，且短期内无收敛趋势；当房屋处于相邻地下工程施工影响时，地基沉降速率大于 **2mm/天**，且短期内无收敛趋势；
    > 2. 因地基变形引起砌体结构房屋承重墙体产生单条宽度大于 **10mm** 的沉降裂缝，或产生最大裂缝宽度大于 **5mm** 的多条平行沉降裂缝，且房屋整体倾斜率大于 **1%**；
    > 4. 两层及两层以下房屋整体倾斜率超过 **3%**，三层及三层以上房屋整体倾斜率超过 **2%**。”

*   **第 5.3.2 条 (砌体结构构件检查)**:
    > “砌体结构构件检查应包括下列主要内容：
    > 2. 查明纵横墙交接处的斜向或竖向裂缝状况；
    > 3. 查明承重墙体的变形、裂缝和拆改状况；
    > 5. 确定裂缝宽度、长度、深度、走向、数量及分布，并应观测裂缝的发展趋势。”

#### **B. GB 50292-2015《民用建筑可靠性鉴定标准》**
*   **第 5.4.4 条 (砌体构件位移/变形评级)**:
    > “当砌体结构构件安全性按不适于承载的位移或变形评定时，应符合下列规定：
    > 1. 对墙、柱的水平位移或倾斜，当其实测值大于本标准表 7.3.10 条所列的限值时，应按下列规定评级...”

### 2.1.1 智能化数据转化逻辑 (Sensor-to-Rule Logic)
在 ABL 场景中，智能体需要将传感器采集的“原始物理量”转化为“工程判定量”。

| 传感器类型 | 采集物理量 | 转化公式/逻辑 | 工程判定参数 (Rule Input) |
| :--- | :--- | :--- | :--- |
| **倾斜传感器** | 轴向偏角 $\theta$ (度/分) | $i = \tan(\theta) \times 100\%$ | **整体倾斜率 ($i$)** |
| **静力水准仪** | 液面高度 $h$ (mm) | $v = \frac{h_2 - h_1}{t_2 - t_1}$ | **沉降速率 ($v$)** |
| **无线裂缝计** | 拉绳位移 $d$ (mm) | $w = d_{now} - d_{initial}$ | **裂缝开展宽度 ($w$)** |

### 2.2 标准转化映射参考 (Reference Mapping)
以下为从“标准明文”到“推理规则”的结构化转化逻辑（参考答案）：

| **标准明文 (JGJ 125 4.2.1-2)** | **结构化解析 (拆解)** | **参考推理规则 (Agent Logic)** |
| :--- | :--- | :--- |
| “因地基变形引起砌体结构房屋承重墙体产生单条宽度大于 **10mm** 的沉降裂缝...” | **条件 A**: 墙体裂缝<br>**阈值**: 宽度 > 10<br>**属性**: 单条、沉降 | `IF crack_type == "settlement"`<br>`AND crack_width > 10` |
| “...或产生最大裂缝宽度大于 **5mm** 的多条平行沉降裂缝...” | **条件 B**: 多条平行裂缝<br>**阈值**: 宽度 > 5 | `OR (crack_pattern == "parallel"`<br>`AND crack_width > 5)` |
| “...且房屋整体倾斜率大于 **1%**...” | **条件 C**: 整体倾斜<br>**阈值**: 倾斜率 > 1%<br>**逻辑连接**: 且 (AND) | `AND building_tilt > 0.01` |
| “...应评定为危险状态。” | **结论**: 状态判定 | `THEN status = "D级 (危险)"` |

### 2.3 推理规则逻辑 (Rule Logic)
基于上述原文，学生需在控制台配置以下逻辑：

*   **规则 1 (排除非结构性干扰)**:
    *   `IF 裂缝深度 == "表层/不穿透" THEN 性质 = "装饰层开裂" (忽略)`
*   **规则 2 (成因鉴别 - 沉降 vs 温度)**:
    *   `IF 裂缝位置 == "底层窗角" AND 形态 == "斜向" THEN 成因 = "沉降"` (对齐 JGJ 125 5.3.2-2)
    *   `IF 裂缝位置 == "顶层两端" AND 形态 == "水平/包角" THEN 成因 = "温度收缩"`
*   **规则 3 (危险性判定 - JGJ 125 4.2.1-2)**:
    *   `IF 单条裂缝宽度 > 10mm AND 房屋整体倾斜率 > 1% THEN 状态 = "地基危险 (D级)"`
    *   `IF 多条平行裂缝宽度 > 5mm AND 房屋整体倾斜率 > 1% THEN 状态 = "地基危险 (D级)"`
*   **规则 4 (基于监测数据的地基稳定性判定 - JGJ 125 4.2.1-1)**:
    *   `IF 房屋处于相邻施工影响 AND 沉降速率 > 2mm/d THEN 状态 = "地基危险 (D级)"`
    *   `IF 房屋处于自然状态 AND 沉降速率 > 4mm/月 THEN 状态 = "地基危险 (D级)"`

### 2.4 大脑逻辑补全 (Code Completion)
**任务**：阅读 2.1 节规范原文，将关键参数及逻辑填入以下 Python 源码中。

```python
# 沉降专家智能体：危险性判定核心模块 (基于 JGJ 125-2016)

def evaluate_building_status(crack_data, tilt_rate, sensor_data):
    """
    crack_data: 裂缝信息字典
    tilt_rate: 由倾斜传感器计算出的倾斜率 (i)
    sensor_data: 包含 'settlement_rate' (mm/d) 和 'context' (施工/自然)
    """
    # TODO: 任务 1 - 补全地基稳定性判定阈值 (参照 JGJ 125 4.2.1-1)
    STABILITY_LIMIT_CONSTRUCTION = 2.0  # 施工影响下限值 (mm/d)
    STABILITY_LIMIT_NATURAL = 4.0       # 自然状态下限值 (mm/月)
    
    # 逻辑 1: 基于 IoT 监测数据的实时预警
    v = sensor_data['settlement_rate']
    if sensor_data['context'] == "construction" and v > STABILITY_LIMIT_CONSTRUCTION:
        return "D_GRADE_DANGEROUS_STABILITY"
    
    # TODO: 任务 2 - 补全基于裂缝和倾斜的静态判定逻辑
    CRACK_LIMIT_SINGLE = 10.0
    TILT_LIMIT = 0.01 # 1%
    
    if crack_data['max_width'] > CRACK_LIMIT_SINGLE and tilt_rate > TILT_LIMIT:
        return "D_GRADE_DANGEROUS_STRUCTURAL"

    return "B_OR_C_GRADE"
```

## Phase 3: 工具调试与挂载 (Tool Crafting)
**目标**：配置 Agent 执行任务所需的“手”。只有校准后的工具才能在 SOP 中被调用。

### 3.1 核心工具参数与考察设计
学生对智能工具的掌握不应只是“接入”，而应通过以下三个实训任务进行深度考察：

#### **任务 A：传感器布设策略 (Deployment Strategy)**
*   **考察点**：学生是否理解结构受力的关键位置。
*   **实训操作**：在 3D 建筑模型上，要求学生从工具箱拖拽 3 个“静力水准仪测点”进行布设。
*   **评分标准**：
    *   **满分**：测点布设在靠近基坑一侧的承重墙转角处，且在远离基坑的稳定区域布设了“基准点”。
    *   **扣分**：测点布设在非承重填充墙上；未设置基准点（无法计算相对沉降）。

#### **任务 B：数据归零与补偿 (Calibration & Zeroing)**
*   **考察点**：学生对测量精度和初始状态的理解。
*   **实训操作**：系统给出一个带有安装偏差的倾斜传感器（初始角度 0.5°）。
*   **要求**：学生必须在智能体控制台中调用 `sensor.zero_calibration()` 函数，并手动输入补偿值。
*   **判定**：若未归零直接运行，智能体会因“初始误差”导致虚假报警，任务失败。

#### **任务 C：异常判别逻辑 (Anomaly Diagnosis)**
*   **考察点**：区分“传感器故障”与“结构危险”。
*   **实训操作**：在数据流中注入一段“剧烈抖动但均值稳定”的噪声数据（模拟大风或车辆经过）。
*   **要求**：学生需在代码中增加一个“滑动平均滤波”逻辑或“持续时间”判定逻辑。
*   **逻辑参考**：
    ```python
    # 学生需要补全的防抖逻辑
    if v > 2.0 and duration > 3: # 只有持续 3 秒以上的速率异常才判定为危险
        trigger_alarm()
    ```

## Phase 4: SOP 流程编排 (Planning)
**目标**：通过拖拽节点，编排 Agent 的标准作业程序。

### 4.1 推荐 SOP 工作流
1.  **数据接入**: `Connect IoT Streams` (实时获取 `DATA_01`, `DATA_02`)
2.  **线索对齐**: `Invoke Memory` (检索现场线索 `CLUE_01` 至 `CLUE_04`)
3.  **规则判定**: `Logic: BrainReasoning` (将传感器角度转化为倾斜率，并应用 JGJ 125 规则)
4.  **自动预警**: `Execute: AlertSystem` (若速率 > 2mm/d 立即触发红色预警)
5.  **生成报告**: `Generate Final Report` (汇总所有数据，输出 A/B/C/D 结论)

## Phase 5: 实战验收 (Execution & Review)
**目标**：自动化执行并给出评分。

### 5.1 验收标准 (Grading Policy)
*   **满分条件**:
    1.  Agent 成功识别出“基坑”是导致沉降的主要外部诱因。
    2.  **成功排除干扰项**：未将顶层水平裂缝（温度）和表面龟裂（粉刷层）计入沉降鉴定依据。
    3.  准确调用 JGJ 125 条文，判定房屋为 D 级危房（假设现场数据：裂缝 12mm，倾斜 1.2%）。
    4.  给出了“先稳后修”的处置建议。
*   **常见扣分项**:
    *   **判定错误**：将温度裂缝误判为沉降裂缝（-20分）。
    *   **感知缺失**：漏掉关键线索（如深基坑）（-10分/项）。
    *   未调用工具测量倾斜率（依据不足）。

## 🚀 进阶思考：从线性训练到迭代工作坊 (Agent Studio)

**构建智能体真的是分步的吗？**
在实际工程中，Phase 1-4 往往是**迭代并行**的：
1.  你在 **Phase 4 (SOP)** 编排流程时，发现 Agent 缺一个“测量精度”的判断，于是你会跳回 **Phase 2 (Brain)** 补充规则。
2.  你在 **Phase 5 (Run)** 运行失败，发现是 Agent 没看到基坑，于是你会跳回 **Phase 1 (Memory)** 强化感知。

**教学建议**：
在实训后期，应鼓励学生进入“自由工作坊模式”，在统一的 Dashboard 中同时调整 Memory、Brain 和 Tools，观察智能体表现的变化。这才是真正意义上的 **AI 协同工程**。
