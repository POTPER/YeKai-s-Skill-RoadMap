# 5.1 实训 Phase 1: 现场踏勘功能设计方案 (Implementation Design)

> **目标**: 仅针对“Phase 1: 现场踏勘与上下文构建”进行界面与交互设计。
> **核心体验**: 模拟工程师带领 AI 实习生进行现场调查，体验“所见即所得”的上下文注入过程。

## 1. 界面布局规划 (UI Layout)

采用 **"沉浸式场景 + 侧边栏助手"** 的布局结构。

```

|  Header: 任务进度 | 当前视角: 无人机/第一人称 | 专注度: 100%      |
+-----------------------------------+---------------------------+
|                                   |                           |
|                                   |  **Agent 状态面板**       |
|                                   |                           |
|                                   |  [ 🧠 认知模型 ]          |

+---------------------------------------------------------------+
```

## 2. 交互功能详解 (Interaction Specs)

### 2.1 引导与提示系统 (Guidance System)
为了解决“感知难点”和“幻觉陷阱”，我们需要设计一套 **Context-Aware (上下文感知)** 的提示系统。

*   **视觉提示 (Visual Cues)**:
    *   **被动提示**: 当鼠标悬停在墙面时，显示半透明的 **“结构网格 (Structural Grid)”**，帮助用户理解哪里是承重墙，哪里是填充墙。
    *   **主动提示**: 如果用户在场景中漫无目的地游荡超过 10秒，Agent 会弹出一个 **“热力图 (Heatmap)”** 提示，高亮显示“应力集中区”（即窗角）。
*   **认知引导 (Cognitive Prompts)**:
    *   **悬停 (Hover)**: 显示 `Scanning...` 动画。
    *   **预判 (Preview)**: 显示简短的工程疑问句，例如：“这里的裂缝形态是否符合剪切特征？”（引导用户去思考“倒八字”）。

### 2.2 线索采集机制 (Collection Mechanism)
1.  **发现 (Spotting)**: 
    *   用户将准心对准裂缝。
    *   系统显示：`Target Locked: Unknown Crack`。
2.  **采集 (Collecting)**: 
    *   点击鼠标左键。
    *   **动画**: 播放“特征提取”特效（线条被提取出来，旋转，匹配“倒八字”模板）。
3.  **解析 (Parsing)**:
    *   弹出 **“认知卡片 (Cognition Card)”**：
        *   **Visual**: 倒八字 (Inverted-V)
        *   **Physics**: 剪切破坏 (Shear Failure)
        *   **Context**: 关联到“不均匀沉降”
    *   **Agent 反馈**: "已确认！这正是我们要找的剪切裂缝。它证明了端部沉降大于中部。"

### 2.3 干扰项与反幻觉 (Noise & Anti-Hallucination)
*   **设计目的**: 训练用户识别“归因谬误”。
*   **干扰项**: **墙面涂鸦 (Graffiti)** 或 **空调外机振动 (AC Vibration)**。
*   **交互**:
    *   用户点击涂鸦。
    *   **系统警告**: `Invalid Context` (无效上下文)。
    *   **Agent 吐槽**: "这只是表面污渍，与结构受力无关。请不要让这些噪点干扰我的判断。"
    *   **惩罚**: 扣除 5% 的“认知能量 (Cognitive Energy)”。

## 3. 数据流与反馈 (Data Flow & Feedback)

### 3.1 状态机 (State Machine)
*   `State: Init`: 任务开始，Agent 处于“白纸”状态。
*   `State: Exploring`: 用户正在操作视角。
*   `State: Analyzing`: 用户点击了线索，Agent 正在分析。
*   `State: Context_Loaded`: 收集到了核心线索（基坑 + 裂缝）。
*   `State: Ready_Next`: 满足晋级条件，解锁 Phase 2 按钮。

### 3.2 关键脚本 (Script)

| 触发对象 | Agent 语音 (Chat) | 记忆日志 (Memory Log) | 视觉反馈 |
| :--- | :--- | :--- | :--- |
| **Start** | "老师，这栋楼情况复杂，我该重点关注哪些部位？" | `[System] Agent initialized.` | 场景加载完成 |
| **点击裂缝** | "看这个走向！这是典型的倒八字裂缝，说明两端沉降比中间大。" | `[Memory] + Visual: Inverted-V Crack` | 裂缝高亮描边 (红色) |
| **点击基坑** | "天啊，旁边居然有个这么深的基坑！还在抽水！这肯定是主因。" | `[Memory] + Env: Deep Excavation` | 基坑区域闪烁警告标示 |
| **点击涂鸦** | "呃... 这虽然不好看，但不影响结构安全吧？" | `[System] Noise filtered.` | 涂鸦显示“无效”叉号 |

## 4. 技术实现路径 (Tech Stack)

鉴于这是一个 Web 实训：
*   **渲染层**: 使用 `Three.js` 或 高清全景图 (`Panolens.js`) 模拟现场。为降低开发成本，初期可使用 **“2.5D 图片热点”** 方案。
*   **UI 层**: HTML/CSS Grid 布局，模拟 IDE 界面。
*   **逻辑层**: JavaScript ES6+ 管理状态机。

## 5. 原型演示 (Prototype Plan)

我们将构建一个单页应用 (`index.html`) 演示 Phase 1：
1.  **背景图**: 一张包含住宅楼和基坑的合成示意图。

3.  **侧边栏**: 实时响应点击事件，动态追加 DOM 元素到 Log 区域。
