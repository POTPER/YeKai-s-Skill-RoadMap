# 智能体构建式土木工程实训平台 - 产品白皮书

## 1. 产品定位 (Product Positioning)

**"From Worker to Architect"**

本平台不是传统的“虚拟仿真操作软件”，而是一个 **“智能体检测机器人构建与训练平台”**。

*   **传统实训**：教学生如何当一名**检测员**（How to use tools）。
*   **本平台**：教学生如何当一名**检测工程师/项目经理**（How to design solutions）。

我们通过让学生**“构建、配置、训练”**一个虚拟检测机器人（Agent），来考核他们对工程规范、检测逻辑和决策体系的深度理解。

---

## 2. 核心价值 (Core Value)

### 2.1 对学生：思维升维
*   **计算思维 (Computational Thinking)**：将模糊的工程问题拆解为标准化的算法流程（SOP）。
*   **系统观 (System View)**：理解“工具-数据-结论”之间的依赖关系，而非孤立地看仪器。
*   **容错与迭代**：在“压力测试”中反复失败并修正策略，低成本积累“老法师”的经验。

### 2.2 对教师：教学创新
*   **无限题库**：后台通过参数化生成无限的“虚拟房屋案例（数据包）”，杜绝抄袭。
*   **过程评价**：不仅看最终结论对不对，更看学生的 **SOP 设计是否严谨**（如：是否考虑了碳化修正？）。

---

## 3. 核心概念模型 (Concept Model)

我们采用 **Agent = Brain + Tools + Planning** 的架构来映射工程实训：

| Agent 模块 | 对应工程概念 | 示例 |
| :--- | :--- | :--- |
| **🧠 Brain (决策大脑)** | 规范判据与专家经验 | JGJ 125 危房判定标准、置信度阈值设置 |
| **🛠️ Tools (感知工具)** | 检测仪器与手段 | 回弹仪、碳化尺、全站仪、裂缝显微镜 |
| **📋 Planning (SOP流程)** | 检测方案与作业指导书 | “先查勘 -> 再普测 -> 疑点精测 -> 综合评定” |
| **💾 Memory (数据档案)** | 现场记录与原始数据 | 测区回弹值数组、历史沉降曲线 |

## 4. 业务流程设计 (User Journey)

学生在平台上的学习路径分为四个阶段：

### 阶段一：考取执照 (License Acquisition)
*   **场景**：微观/专项实训。
*   **动作**：进入单一工具（如回弹仪）的模拟器，练习标准操作（定点、弹击、读数）。
*   **目标**：获得工具的 **“操作授权 (License)”**。只有拿到执照，才能在后续环节调用该工具。
*   **意义**：夯实基本功，确保“原子能力”合格。

### 阶段二：组装智能体 (Agent Assembly)
*   **场景**：智能体工厂。
*   **动作**：拖拽已解锁的工具（Tools）和知识库（Knowledge）到机器人身上。
*   **决策点**：面对“老旧建筑鉴定”任务，是否需要装备“碳化尺”？面对“高层建筑”，是否需要“全站仪”？

### 阶段三：SOP 编排 (Workflow Orchestration)
*   **场景**：可视化流程编辑器。
*   **动作**：拖拽节点定义检测逻辑。
    *   *串行逻辑*：先测回弹 -> 后测碳化。
    *   *分支逻辑*：`IF` 回弹值 < 25MPa `THEN` 启动钻芯验证。
*   **防呆校验**：系统实时检查逻辑漏洞（如：引用了未授权的工具，或遗漏了必要步骤）。

### 阶段四：压力测试与迭代 (Simulation & Iteration)
*   **场景**：虚拟演练场。
*   **动作**：
    1.  系统随机生成 N 个“黑盒房屋”（数据包）。
    2.  学生点击“运行”，看着自己的 Agent 自动跑图。
    3.  **结果反馈**：Agent 可能会在“潮湿地下室”场景中误判，因为学生忘了配置“湿度修正”。
    4.  **修正**：学生回到 Step 2 修改 SOP，重新测试，直到全员通过。

## 5. 技术架构 (Technical Architecture)

### 5.1 前端 (Frontend)
*   **Config Driven UI**: 所有界面由 JSON 配置驱动，支持动态扩展新任务。
*   **Component Factory**: 独立的工具组件库（Scanner, Hammer, Microscope），即插即用。
*   **Visual Editor**: 基于 Canvas/SVG 的拖拽式流程编排器。

### 5.2 后台逻辑 (Backend Logic)
*   **Scenario Generator**: 随机生成房屋数据包（Ground Truth）。
    *   `{ crack_width: 12mm, tilt: 1.2%, carbon: 3.0mm, ... }`
*   **Evaluation Engine**: 
    *   运行学生的 SOP 逻辑。
    *   比对 Agent 结论与 Ground Truth。
    *   生成诊断报告（“你的流程在 Step 3 丢失了精度”）。

---

## 6. 总结

本平台通过 **“元游戏 (Meta-Game)”** 的方式，将枯燥的工程规范学习转化为具有挑战性的 **“机器人训练游戏”**。它不仅解决了传统实训“高消耗、高风险、难复现”的痛点，更将教学目标从“技能熟练度”提升到了“工程系统思维”的高度。
